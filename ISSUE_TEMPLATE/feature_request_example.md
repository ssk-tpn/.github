## 1. 概要・目的
- 機能の概要：
  顧客一覧画面に、電話番号で顧客を検索する機能を追加する。
- 対象ユーザー：
  顧客情報の閲覧権限を持つ顧客対応担当者。
- 現在の課題：
  氏名でしか検索できず、同姓同名の顧客から対象者を探すのに時間がかかる。
- 達成したい状態・期待する効果：
  問い合わせ時に聞き取った電話番号から、対象の顧客情報を確認できる。

## 2. 仕様の管理先
- 仕様の正本：このIssue
- 関連する既存仕様書：なし
- 仕様の確認・合意担当者：
  顧客対応責任者と開発担当者（起票時に実際の担当者を指定する）。

## 3. スコープ

### 今回対応すること
- 顧客一覧画面への電話番号入力欄の追加。
- 電話番号の完全一致検索。
- 一致した顧客の一覧表示と詳細画面への遷移。
- 入力不備・該当なし・検索失敗時のメッセージ表示。
- 既存の顧客閲覧権限によるアクセス制御。

### 今回対応しないこと
- 電話番号の部分一致検索。
- 国際電話番号への対応。
- 電話番号の登録・変更機能。
- 既存の氏名検索との組み合わせ検索。
- 電話番号の重複登録を禁止する変更。

## 4. ユースケース

### UC-01：電話番号から顧客情報を確認する
- 利用者：
  顧客対応担当者。
- 達成したいこと：
  問い合わせをした顧客の登録情報を確認する。
- 事前条件：
  ログイン済みで、顧客情報の閲覧権限がある。
- 基本の流れ：
  1. 担当者が顧客一覧画面で電話番号検索を選択する。
  2. 電話番号を入力して検索ボタンを押す。
  3. システムが一致する顧客を一覧表示する。
  4. 担当者が対象の顧客を選択する。
  5. システムが顧客詳細画面を表示する。
- 完了後の状態：
  担当者が対象顧客の登録情報を確認できる。
- 例外の流れ：
  - 入力不備の場合は、修正を促すメッセージを表示する。
  - 該当なしの場合は、その旨を表示する。
  - 検索失敗の場合は、再試行を促すメッセージを表示する。

## 5. 機能仕様

| 要件ID | 条件・操作 | 期待する動作・結果 |
|---|---|---|
| FR-01 | 検索方法を選択する | 「氏名」「電話番号」を切り替えられる。初期状態は既存の氏名検索とする |
| FR-02 | 電話番号を入力して検索する | 入力値と登録値を同じルールで正規化し、完全一致する顧客を検索する |
| FR-03 | 未入力または形式不正で検索する | 検索を実行せず、入力エラーを表示する。API側でも同じ検証を行う |
| FR-04 | 一致する顧客が存在する | 該当する顧客のID・氏名・登録済み電話番号を表示する。重複する電話番号の顧客もすべて検索対象にする |
| FR-05 | 一致する顧客が存在しない | 「該当する顧客はいません」と表示する |
| FR-06 | 検索結果から顧客を選択する | 対象の顧客詳細画面に遷移する |
| FR-07 | 閲覧権限のない利用者がアクセスする | 電話番号検索を利用できず、検索APIへの直接アクセスも拒否する |
| FR-08 | 通信・サーバーエラーが発生する | 「検索に失敗しました。時間をおいて再度お試しください」と表示し、再試行できるようにする |

### 入出力・データ
- 入力項目：電話番号。
- 正規化ルール：
  - 全角数字を半角数字に変換する。
  - 半角ハイフン「-」と半角・全角スペースを除去する。
  - 上記以外の文字は変換・除去しない。
- 正規化後の許容形式：半角数字10桁または11桁。
- 未入力時のメッセージ：「電話番号を入力してください」。
- 形式不正時のメッセージ：「電話番号は10桁または11桁の数字で入力してください」。
- 検索結果の表示順：顧客IDの昇順。
- 検索結果は1ページ20件とし、超過した場合はページを切り替えられる。
- 電話番号が未登録の顧客は検索対象外とする。
- 検索によって顧客データを変更しない。

### 権限・アクセス制御
- 既存の「顧客閲覧権限」を利用する。
- 未ログインの画面アクセスはログイン画面へ誘導する。
- 検索APIは未認証の場合401、権限不足の場合403を返す。
- 別の閲覧制限が設定された顧客は、その制限を維持する。

### 例外・境界条件
- 正規化後が9桁または12桁の場合は入力エラーとする。
- 同じ電話番号の顧客が複数存在する場合は、閲覧可能な顧客をすべて表示する。
- 新しい検索開始時に、前回の検索結果とエラーメッセージを消去する。
- 検索中は検索ボタンを無効化し、処理終了後に再度有効化する。
- 検索方法を切り替えた場合は、入力値・結果・エラーを消去する。

## 6. 非機能要件・制約
- 性能・処理量：
  検証環境で顧客10万件、同時利用10人、各利用者が5秒間隔で
  5分間検索した場合、検索APIの応答時間の95パーセンタイルを
  1秒以内とする。
- セキュリティ・個人情報：
  検索した電話番号の全文をアプリケーションログに記録しない。
  検索APIのリクエスト本文もログ出力対象外とする。
- 対応環境・互換性：
  現行システムのサポート対象ブラウザで動作する。
- アクセシビリティ：
  入力欄にラベルを付け、キーボードのみで検索・結果選択ができる。
- ログ・監視・運用：
  検索失敗時は電話番号を含めず、エラー種別とリクエストIDを記録する。

## 7. 受け入れ条件

### AC-01：表記の異なる電話番号で検索できる
- 対応する要件：FR-02、FR-04
- Given：
  閲覧可能な顧客Aが「090-1234-5678」で登録されている。
- When：
  以下の入力値で、それぞれ検索する。
  - 09012345678
  - 090-1234-5678
  - ０９０１２３４５６７８
  - 090 1234 5678
- Then：
  いずれも検索結果に顧客AのID・氏名・登録済み電話番号が表示される。

### AC-02：電話番号が重複していても対象を確認できる
- 対応する要件：FR-04、FR-06
- Given：
  同じ電話番号を持つ閲覧可能な顧客が21件登録されている。
- When：
  その電話番号で検索する。
- Then：
  顧客ID昇順で1ページ目に20件、2ページ目に1件表示される。
  各顧客を選択すると、その顧客の詳細画面へ遷移する。

### AC-03：入力不備の場合は検索しない
- 対応する要件：FR-03
- Given：
  電話番号検索を選択している。
- When：
  未入力、9桁、12桁、英字を含む値でそれぞれ検索する。
- Then：
  未入力時は「電話番号を入力してください」と表示される。
  その他の場合は形式不正のメッセージが表示される。
  画面から検索APIは呼び出されない。
  APIへ直接不正値を送った場合も400で拒否される。

### AC-04：該当する顧客がいないことが分かる
- 対応する要件：FR-05
- Given：
  入力する電話番号に一致する顧客が存在しない。
- When：
  有効な形式の電話番号で検索する。
- Then：
  「該当する顧客はいません」と表示され、前回の結果は残らない。

### AC-05：閲覧権限に応じてアクセスが制御される
- 対応する要件：FR-07
- Given：
  未ログインの利用者、または顧客閲覧権限のない利用者である。
- When：
  検索画面または検索APIへアクセスする。
- Then：
  顧客情報は表示・返却されない。
  未ログインの画面アクセスはログイン画面へ誘導される。
  APIは未認証の場合401、権限不足の場合403を返す。

### AC-06：検索失敗後に再試行できる
- 対応する要件：FR-08
- Given：
  検索APIがサーバーエラーを返す。
- When：
  有効な電話番号で検索する。
- Then：
  検索失敗のメッセージが表示される。
  入力値は保持され、検索ボタンが再度有効になる。

### AC-07：既存の氏名検索を引き続き利用できる
- 対応する要件：FR-01
- Given：
  顧客一覧画面を開いている。
- When：
  初期状態で氏名を入力して検索する。
- Then：
  既存仕様どおりの顧客検索結果が表示される。
